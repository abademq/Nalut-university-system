# منصة الجامعة الذكية المتكاملة — النسخة الأولية (MVP)

منصة رقمية موحدة تربط الطلبة وأعضاء هيئة التدريس والمعيدين والموظفين وإدارات الكليات والجامعة،
مع وحدة حضور ذكية مقاومة للتزوير. هذه النسخة تعمل فعلياً وتغطي سيناريو العرض الكامل في قمة تقنية المعلومات.

> A working MVP of a multi-tenant university platform (FastAPI + PostgreSQL + installable Arabic PWA)
> covering roles & permissions, announcements, assignments, grades with an approval workflow,
> dynamic-QR attendance with anti-fraud signals, messaging, service requests and reports.

## ما الذي تتضمنه هذه النسخة

| الوحدة | المحتوى |
|---|---|
| الدخول والصلاحيات | دخول بالبريد أو الهاتف، كلمات مرور مجزأة (scrypt)، قفل بعد المحاولات الفاشلة، تحديد معدل الطلبات، مصادقة ثنائية TOTP إلزامية للإداريين، استعادة الحساب، تدوير رموز الجلسة واكتشاف إعادة استخدامها |
| تعدد الجامعات | كل البيانات معزولة بـ `university_id`، وصلاحيات حسب الدور ← الكلية ← القسم ← المقرر |
| المقررات | الكليات، الأقسام، الفصول، المقررات، الجداول، إسناد الأساتذة والمعيدين، تسجيل الطلبة |
| الإشعارات | صندوق داخلي + إشعارات فورية + SMS عبر مزود خارجي، أولويات (عادي/مهم/عاجل)، استهداف (طالب/مقرر/قسم/كلية/دفعة/جامعة)، جدولة، فصل بين الإعلانات والملاحظات الأكاديمية والتحذيرات الرسمية مع تحديد الجهة المخولة لكل نوع |
| الواجبات والبحوث | نشر، مواعيد فتح وتسليم، رفع من الهاتف، فحص أمني للملفات، نسخ متعددة للتسليم، حالات (لم يبدأ/قيد العمل/تم التسليم/متأخر/تمت المراجعة)، تقييم وملاحظات ونشر الدرجة، تذكير تلقائي قبل الموعد |
| النتائج | رصد الدرجات، استيراد CSV/Excel مع فحص قبل الاعتماد، حساب المجموع والتقدير، سير اعتماد (مسودة ← مرفوعة ← معتمدة ← منشورة)، سجل لكل تعديل بسببه ومنفذه |
| الحضور | QR ديناميكي يتجدد كل 15 ثانية، رمز رقمي بديل، منع إعادة الاستخدام، مؤشرات مخاطر (نطاق جغرافي، جهاز مشترك، جهاز جديد)، صورة حية اختيارية مشفرة، مراجعة بشرية، تسجيل يدوي بسبب، دوام الموظفين (دخول/انصراف)، تنبيهات تجاوز الغياب، سلسلة تجزئة تكشف التعديل الصامت |
| التواصل | محادثات مرتبطة بالمقرر وفق سياسة المؤسسة، مرفقات، إبلاغ عن الإساءة ومعالجته |
| المعاملات الإدارية | طلبات (إفادة قيد، كشف درجات، عذر غياب، تظلم...) تُوجَّه للمكتب المختص، إحالة، طلب مستندات، اعتماد/رفض مع إشعار |
| التقارير | لوحات للإدارة والأستاذ، مقارنة الكليات/الأقسام، الحضور اليومي/الأسبوعي/الشهري مع تصدير CSV، دوام الموظفين، الطلبة المحتاجون للمتابعة |
| التدقيق | سجل تدقيق متسلسل بالتجزئة مع أداة تحقق من السلامة |

واجهة الويب عربية (RTL) ومتجاوبة وقابلة للتثبيت على الهاتف كتطبيق (PWA)، وتخدم كل الأدوار.
الواجهة البرمجية موثقة تلقائياً على `/api/docs` وجاهزة لتطبيق Flutter (انظر [docs/architecture.md](docs/architecture.md)).

## التشغيل السريع (للتطوير والعرض)

المتطلبات: Python 3.12 أو 3.13 (على Windows فعّل خيار «Add python.exe to PATH» أثناء التثبيت).

**أسهل طريقة:** على Windows انقر مرتين على `start-windows.bat`، وعلى macOS/Linux نفّذ `./start.sh`.
أول تشغيل يثبّت المتطلبات وينشئ البيانات التجريبية، ثم افتح http://localhost:8000.
لإعادة البيانات التجريبية من البداية (مثلاً قبل العرض): `start-windows.bat reset` أو `./start.sh reset`.

أو يدوياً:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements-dev.txt
cd backend
python -m app.seed --reset        # بيانات تجريبية (SQLite افتراضياً)
uvicorn app.main:app --reload     # ثم افتح http://localhost:8000
```

كلمة المرور لكل الحسابات التجريبية: `Demo@12345`

| الحساب | الدور |
|---|---|
| `s.ali@nalut.edu.ly` (أو الهاتف `0920000001`) | طالب |
| `t.ahmed@nalut.edu.ly` | عضو هيئة تدريس |
| `ta.omar@nalut.edu.ly` | معيد |
| `registrar@nalut.edu.ly` | موظف (مكتب التسجيل) |
| `dean.it@nalut.edu.ly` | إدارة كلية تقنية المعلومات |
| `president@nalut.edu.ly` | إدارة الجامعة |
| `platform@demo.ly` | مشرف المنصة (يُطلب منه تفعيل المصادقة الثنائية عند أول دخول) |
| `student@demo2.edu.ly` | طالب في جامعة أخرى (لإثبات عزل البيانات) |

في البيانات التجريبية أُوقف إلزام المصادقة الثنائية لحسابات جامعة نالوت الإدارية لتسهيل العرض؛
يمكن تفعيله من «إعدادات المؤسسة»، وهو مفعّل افتراضياً لأي جامعة جديدة.

**الكاميرا على الهاتف** تتطلب HTTPS. للعرض من هاتف حقيقي شغّل الخادم خلف شهادة TLS
(أو نفق HTTPS)، أو استخدم «الرمز الرقمي» البديل المعروض تحت رمز QR.

### باستخدام Docker و PostgreSQL

```bash
cp .env.example .env              # واملأ SECRET_KEY و DATA_ENCRYPTION_KEY
docker compose up --build -d
docker compose exec api python -m app.seed   # اختياري: بيانات تجريبية
# فحص الملفات بـ ClamAV: docker compose --profile scan up -d ثم CLAMD_ADDRESS=clamav:3310
```

## الاختبارات

```bash
cd backend && python -m pytest -q
# على PostgreSQL:
TEST_DATABASE_URL=postgresql+psycopg://user:pass@localhost/nus_test python -m pytest -q
```

تغطي الاختبارات سيناريو معايير النجاح كاملاً، والعزل بين الجامعات، ومنع تجاوز الصلاحيات،
ومقاومة تزوير الحضور (رموز منتهية، رموز مزورة، إعادة إرسال الطلب، جهاز مشترك، النطاق الجغرافي،
الصورة الحية)، وكشف التلاعب بالسجلات، وسير اعتماد النتائج، وفحص الملفات المرفوعة.

## هيكل المستودع

```
backend/app/
  main.py            تطبيق FastAPI، ترويسات الأمان، تقديم واجهة الويب
  models.py          نموذج البيانات (كل الجداول مرتبطة بالجامعة)
  deps.py            قواعد الصلاحيات ونطاق الوصول
  security.py        كلمات المرور، JWT، TOTP، التشفير، تحديد المعدل
  attendance.py      رموز QR المتغيرة، التحقق، تقييم المخاطر، سلسلة السلامة
  notifications.py   خدمة الإشعارات متعددة القنوات ومزودو Push/SMS
  files.py           التخزين الآمن وفحص الملفات
  grades.py          حساب النتائج والاستيراد
  audit.py           سجل التدقيق المتسلسل
  biometrics.py      نقطة توصيل نظام متخصص للتحقق من الوجه
  worker.py          المهام الخلفية (الجدولة، التذكير، إغلاق الجلسات، الحذف وفق سياسة الاحتفاظ)
  routers/           واجهات API لكل وحدة
  seed.py            البيانات التجريبية
web/                 واجهة PWA عربية (Preact + htm بدون أدوات بناء)
docs/                التوثيق
```
