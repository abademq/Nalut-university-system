## الاختيارات ولماذا

| المكوّن | الاختيار | السبب |
|---|---|---|
| الخادم | Python + FastAPI | سرعة تطوير، توثيق OpenAPI تلقائي، تحقق من المدخلات عبر Pydantic |
| قاعدة البيانات | PostgreSQL (SQLite للتطوير والاختبار) | علائقية، قيود فريدة تحمي من التكرار، جاهزة للتوسع |
| الواجهة | Preact + htm بلا أدوات بناء | خفيفة (~13KB)، تعمل دون اتصال بالإنترنت أثناء العرض، متوافقة مع CSP صارمة |
| تطبيق الهاتف | PWA الآن، Flutter لاحقاً | الـ PWA تُثبت على Android/iOS وتستخدم الكاميرا والموقع؛ Flutter يُضاف على نفس الـ API |
| المهام الخلفية | خيط داخل الخادم أو عملية `python -m app.worker` | بسيط للنموذج الأولي، ويُستبدل بطابور (Celery/RQ) عند الحاجة |

## تعدد الجامعات والكليات

- عزل منطقي: كل جدول يحمل `university_id` (مباشرة أو عبر المقرر)، وكل استعلام يُقيد به.
- إعدادات لكل جامعة (`universities.settings`) مع تجاوزات لكل كلية (`faculties.settings`):
  الهوية البصرية، سلم التقديرات، سياسة الحضور ومستويات التحقق، سياسة المراسلة، الإشعارات وSMS،
  أنواع وأحجام الملفات، اللغات. القيم الافتراضية في `app/tenancy.py`.
- عند الحاجة لعزل أقوى (جامعات منفصلة قانونياً) يمكن نشر نسخة مستقلة بقاعدة بيانات مستقلة لكل
  جامعة دون تغيير في الشيفرة، أو تفعيل Row-Level Security في PostgreSQL على `university_id`.

## الأدوار

`platform_admin` → `university_admin` → `faculty_admin` → `staff` / `teacher` / `assistant` / `student`.
الصلاحية = الدور + النطاق (الجامعة، الكلية، القسم، المقرر). انظر [security.md](security.md).

## واجهة API لتطبيق Flutter

- الدخول: `POST /api/auth/login` مع ترويسة `X-Client: mobile` → `access_token` + `refresh_token`.
- التجديد: `POST /api/auth/refresh` بالجسم `{"refresh_token": "..."}` (يُدوَّر في كل مرة).
- رمز الإشعارات: `POST /api/me/devices` `{platform: android|ios, token}`.
- الحضور: `GET /api/attendance/sessions/{id}/requirements` ثم `POST /api/attendance/check-in`
  (multipart: `payload`, `nonce`, `latitude`, `longitude`, `selfie`) مع ترويسة `X-Device-Id`.
- قائمة كاملة بالمسارات والنماذج على `/api/docs`.

## إضافة وحدات مستقبلية

كل وحدة = ملف نماذج في `models.py` + راوتر في `routers/` + صفحة في `web/js/views/`، وتستخدم
نفس طبقة الصلاحيات والتدقيق والإشعارات. مثال: إضافة RFID = قيمة `method="rfid"` ونقطة نهاية
لقارئ البطاقات موقعة بمفتاح الجهاز، دون تغيير جداول الحضور.

## حدود النموذج الأولي (بصراحة)

- الجداول تُنشأ بـ `create_all`؛ الإنتاج يحتاج ترحيلات (Alembic).
- محدد المعدل داخل الذاكرة (نسخة خادم واحدة)؛ لعدة نسخ يُنقل إلى Redis.
- مزودا Push وSMS في وضع «log» افتراضياً؛ وضع «http» عام يتطلب مزوداً فعلياً.
- البريد الإلكتروني لاستعادة الحساب غير موصول بعد (يُرسل عبر SMS أو يظهر في سجل الخادم في التطوير).
- لا يوجد تطبيق Flutter في هذا المستودع بعد؛ الواجهة الحالية PWA.
