# خارطة الطريق بعد النموذج الأولي

مرتبة حسب الأولوية المقترحة. كل بند يستخدم نقاط التوسعة الموجودة حالياً.

## 1. تجهيز الإنتاج
- ترحيلات Alembic، Redis لمحدد المعدل والطوابير، نسخ احتياطي مع اختبار استعادة دوري.
- إرسال البريد الإلكتروني (استعادة الحساب، ملخصات أسبوعية).
- مراقبة مركزية للأخطاء والسجلات (مثل OpenTelemetry + Sentry).

## 2. تكامل SMS والإشعارات الفورية
- ربط `HttpSmsProvider` بمزود محلي (مثل مزودي الاتصالات في ليبيا) وتسجيل حالة التسليم.
- بوابة Push تحمل مفاتيح Firebase Cloud Messaging و APNs، وتطبيق الهاتف يرسل رمزه إلى `/api/me/devices`.
- قوالب إشعارات قابلة للتعديل لكل جامعة.

## 3. تطبيق Flutter
- يستهلك نفس الـ API (انظر architecture.md)، مع تخزين رمز التحديث في Keychain/Keystore،
  ومسح QR أصلي، وإشعارات فورية، وربط معرّف الجهاز بمفتاح في العتاد الآمن (Play Integrity / App Attest)
  لرفع موثوقية إشارة «الجهاز».

## 4. RFID / NFC
- قارئات عند البوابات والقاعات ترسل `(card_uid, reader_id, timestamp)` موقعة بمفتاح القارئ إلى
  نقطة نهاية مخصصة، تُسجل بـ `method="rfid"`؛ ويمكن جعلها عاملاً ثانياً في سياسة `high`.

## 5. التحقق البيومتري (اختياري)
- اختيار مزود متخصص بالمطابقة وفحص الحيوية ومقاومة الهجمات، بعد تقييم أثر الخصوصية والموافقة
  الصريحة، وتنفيذه عبر `FaceVerifier` في `app/biometrics.py`. تبقى النتيجة إشارة للمراجعة لا قراراً.

## 6. الذكاء الاصطناعي
المبدأ: مساعد لا يتخذ قرارات نهائية في النتائج أو العقوبات أو الحرمان، ويعمل فقط على بيانات
مسموح للمستخدم برؤيتها، ويُظهر مصادره.

| الوظيفة | التصميم |
|---|---|
| أسئلة اللوائح والخدمات | استرجاع (RAG) من مستودع وثائق رسمية معتمدة فقط، مع الاستشهاد بالمادة والوثيقة |
| تلخيص الإعلانات الطويلة | يُولَّد عند الطلب ويُعرض مع النص الأصلي |
| مساعدة الطالب في فهم درجاته | يبني على `/api/me/insights` (موجود حالياً كقواعد شفافة) ويشرحها بلغة طبيعية |
| ملخص أداء المقرر للأستاذ | يبني على `/api/reports/*` ضمن نطاق صلاحياته فقط |
| بحث الموظفين في الإجراءات والنماذج | نفس مستودع الوثائق المعتمدة |
| أنماط غير معتادة في السجلات | يبني على `/api/attendance/anomalies` وسجل التدقيق، ويرفع تنبيهاً لمراجعة بشرية |

تنفيذياً: وحدة `assistant` تستدعي نموذج اللغة من الخادم فقط (المفتاح لا يصل للعميل)، وتمرر له
نتائج استدعاءات API تمت بصلاحيات المستخدم نفسه، وتسجل الأسئلة والمصادر في سجل التدقيق.

## 7. التكامل مع أنظمة الجامعة القائمة
- استيراد دوري للطلبة والتسجيل والدرجات من نظام شؤون الطلبة (الاستيراد الحالي CSV/Excel أساس لذلك).
- تسجيل دخول موحد (SAML/OIDC) عند توفره لدى الجامعة.
